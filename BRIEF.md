## 1. Цель редизайна — одной фразой

Превратить текущий тёмно-фиолетовый «инди-лендинг» в **премиум-страницу уровня Apple/Linear/Arc**, визуально консистентную с iOS-приложением SOND, чтобы:

1. Поднять воспринимаемое качество продукта (поддерживает $99.99/год ценник).
2. Сделать страницу инструментом конверсии: посетитель → trial в App Store.
3. Снять диссонанс между сайтом (сейчас dark/purple) и iOS-приложением (warm-light/blue glass).

**Основная метрика, которую страница должна двигать:** click-through на App Store с hero и pricing блоков.

## 1а. Чем плох текущий сайт (что чинить в первую очередь)

Заказчик прямо говорит: «сайт уебанский и тексты плохие, какие-то эмоджи».

**Конкретные провалы текущей версии:**

1. **Эмоджи как иконки** — `💼 🎓 🤝 🎤 💬 📥 📄 🔒 ☁️ 🔍`. Дёшево, в 2026 это маркер любительства. Нужны: SVG line-icons (Phosphor / Lucide / SF Symbols-стиль), монохромные, тонкая обводка.
2. **Дискоданс с iOS app** — сайт тёмный фиолетовый, app warm-light blue glass.
3. **Косые тексты** — генеричные формулировки, повторы, рваный ритм. Надо переписать всё с нуля.
4. **«Видео демо» как plain placeholder** — заглушка `<div>` с серым фоном выглядит как недоделанный сайт.
5. **Pricing card с emoji-галочками** `✓` — заменить на тонкие SVG checkmarks.

## 3. Визуальная ДНК — выровнять сайт с iOS-приложением

`reference_ios/DesignSystem.swift` — это источник правды. Ключевые токены ниже.

### Цвета (light mode по умолчанию для лендинга)

| Роль | Light | Dark |
|------|-------|------|
| `bg.primary` (warm) | `#FAF9F5` (тёплый off-white) | `#1C1C1E` |
| `bg.secondary` | `#F7F7FC` | `#2C2C2E` |
| `bg.card` | `rgba(255,255,255,0.7)` | `#3A3A3C` |
| `text.primary` | `#262633` | `#F5F5F7` |
| `text.secondary` | `#73738C` | `#A1A1A6` |
| `accent.blue` (precise) | `#4A90FF` | `#64B5F6` |
| `accent.blue.soft` | `#99CCFF` | `#90CAF9` |
| `accent.red` (recording) | `#FF4757` | `#FF6B7A` |
| `accent.mint` | `#99E6D1` | `#80CBC4` |

**Главный градиент кнопки записи / CTA:**
`linear-gradient(135deg, #99CCFF → #4A90FF)` (primary)
Recording-теме → `linear-gradient(135deg, #FF4757 → #FFA6B3 → #99CCFF)`

**Glass surface (для премиум-карточек):**
- white 25% (light) / 8% (dark) с border `white 30%` / `white 12%`
- `backdrop-filter: blur(20px)`
- мягкая тень: `0 8px 32px rgba(0,0,0,0.04)` + `0 1px 1px rgba(0,0,0,0.06)`

### Типографика

- **System font stack** (как iOS): `-apple-system, BlinkMacSystemFont, "SF Pro Display", "SF Pro Text", system-ui, sans-serif`
- Hero H1: `52-64px, weight 200 (ultraLight)`, letter-spacing -0.03em
- Section H2: `34-40px, weight 200`
- H3: `22-28px, weight 400`
- Body: `16-18px, weight 400`
- Caption: `14px, weight 500`
- Линейный rhythm: `lineHeight 1.5` для body, `1.1-1.15` для заголовков

### Корнеры

| Размер | Px |
|--------|-----|
| small | 8 |
| medium | 16 |
| large | 24 |
| xl | 32 |
| pill | 9999 |

### Spacing (8pt grid)

`4 / 8 / 16 / 24 / 32 / 48 / 64`

### Тон визуала

- **Warm, не cold.** Тёплый бежевый off-white вместо чёрного.
- **Glassmorphism, не flat.** Полупрозрачные карточки + blur + тонкие highlights.
- **Один акцент за раз.** Синий (precise blue) — primary; красный — только для recording-метафоры; mint — точечно.
- **Soft shadows.** Никаких жёстких теней — всегда multi-layer.
- **Микроанимации:** hover lift `translateY(-2px)`, shadow deepen, breathing scale `1.0 ↔ 1.02`.

## 5а. Маркетинговый контекст — ОБЯЗАТЕЛЬНО прочитать перед стартом

Файл `brand/SOND_marketing_context.md` (108 KB, 1422 строки) — это полное customer-research досье. Это не «дополнение», это первичный источник для рерайта копи и для расстановки приоритетов на странице. Без него Claude Design сделает красивый, но мимо аудитории.

### Что внутри

| Раздел | Что даёт для лендинга |
|---|---|
| §1 Product snapshot, JTBD | Что люди НА САМОМ ДЕЛЕ покупают (не фичи, а эмоции) — формулировки для hero и Final CTA |
| §2 Category & market context | Customer language: как люди называют проблему и решение — те самые слова в заголовки и подзаголовки |
| §3 Audience map (5 персон) | Менеджер / студент / коуч / предприниматель / контент-мейкер — для блока Use cases (заменить шаблонные кейсы на конкретные сценарии этих персон) |
| §4 Trigger-to-purchase journey | Триггеры, поисковые запросы, моменты решения и срыва покупки — для микро-копи CTA, hero subtitle, объяснений в pricing |
| §5 Competitor landscape | От чего отстраиваться: что обещают Otter / Fireflies / Voice Memos — наши формулировки должны звучать иначе |
| §6 Awareness level map (Schwartz) | Кто на лендинг приходит на каждом уровне осознанности — как hero должен говорить с problem-aware и solution-aware одновременно |

### Как Claude Design должен это использовать

1. **Перед первой генерацией** — прочитать §3 (5 персон) и §4 (триггеры). Это меняет акценты в hero и порядок секций.
2. **При переписывании Use cases** — взять реальные триггеры из §4 (например, «после совещания с тремя руководителями я снова забыл, кто что обещал»), а не выдумывать абстрактные сценарии.
3. **При написании hero и Features** — использовать customer language из §2, не маркетинговый словарь.
4. **При формулировке Pricing-объяснений** — посмотреть в §4 «Причины отказаться в последний момент» и снять эти возражения текстом на странице.
5. **При построении Awareness-логики** — hero должен зацепить problem-aware (большинство трафика), а pricing/features добивать solution-aware.

### Приоритет источников при конфликте

`SOND_marketing_context.md` > `BRAND_PLATFORM.md` > текущая копи в `index_ru.html`.

(BRAND_PLATFORM — про голос. Marketing context — про что говорить и кому. Текущая копи — только для понимания структуры.)

## 6. Копирайтинг — переписать ВСЕ тексты с нуля

Это обязательная часть, не «по желанию». Текущая копи на сайте — рваная, генеричная, с эмоджи и ритмическими провалами. Берём только смысл блоков, сами формулировки выкидываем.

### 6.1 Голос SOND (из `brand/BRAND_PLATFORM.md`)

Четыре характеристики голоса:

| Характеристика | Что значит |
|---|---|
| Конкретный | Всегда пример AI-инсайта вместо абстракции |
| Разговорный | «Знаете это чувство…» — но без панибратства |
| С характером | Лёгкая ирония, наблюдательность, не сарказм |
| Показывающий | Show, don't tell — результат вместо описания процесса |

**Словарь бренда — используем:**
встреча, разговор, запись, инсайт, паттерн, разбор, конспект, заметил, увидел, пропустил, скрытое, невысказанное.

**Запрещённые слова (любая встреча — переписать):**
революционный, инновационный, уникальный, лучший в мире, game-changing, cutting-edge, disruptive, решение, обеспечивает, позволяет, предоставляет, платформа (про продукт), экосистема, raised the bar, мирового уровня.

### 6.2 Humanizer-правила — обязательно к соблюдению

Сайт — текст для людей, не для AI-индексации. Применять правила humanizer'а в первом драфте, не пост-фактум.

| Запрещено | Почему | Как делать |
|---|---|---|
| Эмоджи в любом виде (💼 ✓ 🔒 и т.д.) | Маркер любительства, диссонанс с премиум-визуалом | Тонкие SVG line-icons, 1.5px stroke |
| Rule of three («быстро, удобно и просто») | Шаблон AI-копи | Один точный аргумент или два контрастных |
| AI-словарь: crucial, leverage, seamless, vibrant, intricate, pivotal | Палево AI-генерации | Простые глаголы: записывает, показывает, находит |
| Negative parallelism («Не просто X — это Y») | Используется в текущем тексте 4+ раз | Прямое утверждение без отрицания |
| Sycophantic intro («Знакомьтесь:», «Представляем:») | Корпоративный мусор | Начинать с конкретики или вопроса |
| Generic positive endings («Работает идеально», «Будущее голосовых заметок») | Пусто | Конкретный следующий шаг или цитата |
| Em dash вместо точки или запятой подряд 3+ раз | Ритм рвётся | Чередовать точки, запятые, тире осознанно |
| Ing-salads («showcasing», «enhancing» — в EN; «обеспечивая» — в RU) | Плоский ритм | Активные глаголы в личной форме |
| CAPS HEADINGS, Title Case Headings | Дёшево | Sentence case для всех заголовков |
| Curly quotes "" внутри тегов | Сбивает рендеринг | Прямые `"` или французские `«»` в RU |

### 6.3 Конкретные замены — пример для каждого блока

**Hero:**
- Сейчас: «Саммари вокруг полно. Детального разбора — ни у кого.»
- Оставить близко по смыслу, но проверить ритм. Subtitle переписать — текущий длинный и с rule of three («что решили, что пропустили, о чём промолчали»).

**Conversation Types — заголовки карточек:**
- Сейчас: «Рабочая встреча» + emoji 💼. Менять на просто «Рабочая встреча» + SVG-иконка с тонкой обводкой (briefcase outline, 24×24px, stroke 1.5).
- Описания карточек переписать в одну строку с конкретным примером, не общими словами.

**Features — выкинуть emoji-иконки:**
- 💬 → SVG chat outline
- 📥 → arrow-down-to-line
- 📄 → file-text
- 🔒 → lock
- ☁️ → cloud
- 🔍 → search

**Use cases — отзывы с цитатами:**
- Цитаты оставить (они хорошие — конкретные, разговорные).
- Списки под цитатами («Неочевидные сигналы собеседника» и т.п.) — пересмотреть на rule-of-three. Сейчас все 4 кейса — ровно 3 буллета. Шаблонно. Сделать 2 / 3 / 2 / 4 для естественности.

**Pricing — `✓` → SVG check (1.5px stroke):**

- Подзаголовок «120 минут бесплатно» дублируется с tag-line «Бесплатно навсегда» — оставить одно.

**Final CTA:**
- Сейчас: «Запишите следующую встречу. 120 минут бесплатно. Хватит на 3-4 разговора. Посмотрите, сколько вы обычно пропускаете.»

### 6.4 Что в текущих текстах оставить (это работает)

## 7. Технические ограничения для финального экспорта

- **Standalone HTML** (один файл предпочтительно, либо HTML + CSS).
- Без JS-фреймворков (React/Vue не нужно — статика).
- Шрифты: только system stack (не подгружать Google Fonts — Inter заменить системными).
- **Zero emojis.** Ни в HTML, ни в alt-text, ни в meta-tags. Все иконки — inline SVG, line-style, 1.5px stroke, монохром (currentColor). Источник для подбора: Phosphor Icons / Lucide / SF Symbols (адаптировать в SVG).
- Изображения: использовать PNG из `screenshots/` (имена сохранены — `01_recording.png`, `03_summary.png` и т.д.) и `brand/app-icon.png`, `brand/favicon.svg`.
- Респонсив: mobile-first, breakpoints `768px` и `1024px`.
- Производительность: лёгкий вес, без декоративных тяжёлых ассетов.
- Demo placeholder заменить на стилизованный device frame (iPhone-силуэт + автоплей-static превью или дизайн-плейсхолдер «Скоро»), а не серый `<div>`.
